- 反汇编发现 6 条自定义 VM 指令（mov_r/add_r/store_r/load_r_s/link_s/copy_s）→ 触发点：自定义 VM 寄存器/段寄存器字段长度
- 假设：set_s(idx_a, idx_b) 接收 u32 idx → idx_b 用 u32 wrap 减法可下溢 → 动作：set_s(3, 0x100000000-0x108)
- 观察：set_s(3, 0xFFFFFFE8) → link_s(1,3) 让 s1.idx_b = s3.idx_b - 0x108 = 0xFFFFFFE0 → 触发越界
- 假设：copy_s(1, 0x100) 触发 memcpy(vm_mem+s1.idx_a, vm_mem+s1.idx_b, 0x100) → 假设：src 是用户控制的任意 32 位值
- 动作：set_s(1, 0x200) + link_s(1,3) + copy_s(1, 0x2000) 把栈拷到 vm_mem+0x200 → 多次 add_r+store_r 写 ROP
- 假设：栈迁移 + 已有 ret2libc 链 → 动作：构造 ret + pop rdi + binsh + system 链写到 vm_mem+0x2000
- 观察：迁移后栈跳到 ROP 区域 → system('/bin/sh') → 完成
failed_attempts:
- 试图用 set_s(3, 0x300) 直接越界 → 失败：长度未触发 u32 wrap
- 试图用 store_r 单字节写 → 失败：受 VM 指令限制
- 试图不解 link_s 直接 memcpy → 失败：idx_a/idx_b 必须先 link

- 自定义 VM 题逆向重点在寄存器/段寄存器字段长度

- 栈迁移 + setcontext / leave;ret 组合是 VM 题的 RCE 通杀套路

- 自定义 VM 逆向（指令编码 / 寄存器 / 段寄存器语义）
