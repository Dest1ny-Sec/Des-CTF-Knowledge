# 2026山东省赛总决赛 Misc5-模型黑盒测试

> **状态：部分分析**。附件未提供可运行的查询端点，`codeword_hashes` 的构造方式无法离线验证，
> 因此本文只记录**已确证的结构事实**与**可验证的攻击思路**，不虚构最终 flag。

## 题目

```
连接题目提供的 CPU 查询端点，发送 JSON Lines。

请求 info：{"op":"info"}
请求查询：{"x":[48 个有限浮点数]}
响应：{"scores":[8 个分数],"remaining":剩余次数}
每次查询输入范数不得超过 64；总预算 65536；分数保留 10 位小数。
```

`manifest.json` 关键字段：

| 字段 | 值 | 含义 |
|---|---|---|
| `dimension` | 48 | 输入维度 |
| `outputs` | 8 | 输出维度 |
| `budget` | 65536 | 查询预算 |
| `precision` | 10 | 分数小数位 |
| `codeword_hashes` | 64 项 | RS 码字哈希 |
| `receipts` | 64 项 | 收据 |
| `salt` | 16B | 盐 |
| `nonce` | 12B | 随机数 |
| `archive` | 54B hex | 归档密文 |

`archive.bin` 是 54 字节，`manifest.archive` 是它的十六进制副本（已核对一致）。

## 已确证的事实

### 1. 密文已给出

```python
import json
d = json.load(open("manifest.json"))
arch = bytes.fromhex(d["archive"])      # 54 字节
assert arch == open("archive.bin","rb").read()
```

`file` 命令会把它误判为 "OpenPGP Secret Key"，但实际没有 OpenPGP 包头（`\x99`/`\xC3` 之类），是误判。

### 2. 64 = RS(64, 48)

`dimension=48`、码字数 `64`，这正好是 **RS(n=64, k=48)** 的码长与信息位。
64 个码字哈希对应 RS 编码后的 64 个码字，每个码字由 48 维秘密线性生成。

### 3. 预算远大于维度

```
budget=65536 = 2^16  >>  dimension=48
```

这个比值（1365:1）是关键信号：**绝对不需要随机采样**，一定存在线性或分段线性的捷径。

## 攻击思路（基于题面提示，可验证部分）

题目给的实验提示原文：

> 先比较同一方向的正负输入，再在一个正方向附近做小幅扰动。若响应在某些方向被截断，
> 沿一条直线比较二阶差分，分段边界处的梯度跳变比单个分数更有信息。

这直接指向**分段线性模型**：

### 步骤 1：测对称性（2 次查询）

```
f(x)  vs  f(-x)
```

若模型是纯线性 `f(x) = Wx + b`，应有 `f(-x) = -f(x) + 2b`；若 `b=0` 则完全反对称。
这一步只需 2 次查询，就能判断是否需要非线性处理。

### 步骤 2：基向量解系数（48 次查询）

```
for i in range(48):
    x = zeros(48); x[i] = 1.0
    s_i = query(x)
```

得到 `W` 的每一列（对应 8 个输出各一列）。总计 48 × 8 = 384 个数，远低于 65536。

注意输入范数限制 `|x| ≤ 64`，取 `x[i]=1` 完全安全。

### 步骤 3：二阶差分定位分段边界

若响应被截断（在某些方向非线性），沿一条直线 `x = t·d` 采样：

```
Δ²f = f(t+ε) - 2f(t) + f(t-ε)
```

边界处 `Δ²f` 跳变。沿跳变方向继续二分，能定位每段的分界点。

### 步骤 4：对照 manifest 校验

还原出秘密后，用 `salt/nonce` 计算 RS 码字哈希，与 `codeword_hashes` 比对。
若 64 项全中，说明恢复正确。

## 尚未完成的部分

**我无法在离线环境确认 `codeword_hash` 的具体构造**。尝试过的组合都失败：

- `sha256(salt + nonce)` — 不匹配
- `sha256(salt + arch)` — 不匹配
- `sha256(salt + b'\x00' + nonce)` — 不匹配

原因：码字哈希需要**码字本体**（由秘密线性生成）参与，而码字必须通过真实 oracle 或从题目给的服务推导。附件里只有哈希，没有码字。

**因此这道题需要连上题目服务才能完成。** 本文的价值在于把"看到预算远超维度的黑盒 oracle 时该怎么想"这条路记录下来。

## 出题视角

这类题在 2025-2026 开始流行，因为**AI 模型本身成了被攻击对象**。真实世界对应：

- 通过 API 查询抽取模型参数（model extraction）
- 通过对抗样本探测模型决策边界
- 利用线性层的可解性绕过"预算"这种看似严格的限制

防御的正确做法不是限制查询次数，而是**限制单次查询的信息量**（如加入噪声、输出量化、或对查询做非线性变换）。本题用 `precision=10` 小数点保留 10 位，其实是在**放大**信息量 —— 反而方便攻击者。
